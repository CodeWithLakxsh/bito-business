# Biteo Business

Company and business management platform for the Biteo ecosystem.

**Biteo Business** is a Flutter-based admin dashboard used to operate the Biteo food-delivery/restaurant platform. It is the internal operations panel for managing vendors, users, orders and earnings, offers and coupons, notifications, support tickets, and AI-assistant conversations. It is built on Google Firebase (Authentication, Cloud Firestore, Cloud Storage) and integrates a Cloud Run endpoint for push notifications and a Telegram bot for operational alerts.

## Official Website

Biteo's official website: https://www.biteo.in/

> **Warning — authentication architecture.** The current admin gate uses a **client-side TOTP check** with a compile-time secret. This is a **CRITICAL SECURITY ARCHITECTURE ISSUE** and is documented as such. Any secret compiled into a Flutter client can be extracted. It is recommended that admin authentication be moved to a **server-side authentication/verification** mechanism before production deployment. See [docs/security.md](docs/security.md).

## Features

- **Admin access gate** — client-side TOTP (RFC 6238-style) one-time code entry. *(Security limitation documented — see Security section.)*
- **Dashboard** — live counts of total/active/blocked vendors, restaurants open, and recently added vendors.
- **Vendor onboarding** — create a Firebase Auth vendor account, upload a logo to Cloud Storage, and write the vendor document (with geolocation) to Firestore.
- **Vendor management** — activate/block vendors, toggle open/closed, view details.
- **User management** — list users, block/unblock, view per-user analytics (order counts, spend, Biteo points, most-ordered item) and order history.
- **Vendor join requests** — review and approve/reject requests.
- **Notifications** — compose and send notifications to all users, all vendors, a single user, or a single vendor (written to Firestore).
- **Push notifications** — send push notifications through the configured Cloud Run endpoint.
- **Offers & coupons** — create, activate/disable, and delete offers; create coupon codes.
- **Earnings & analytics** — lifetime and today's GMV, platform profit, and order statistics derived from `orders`.
- **Support tickets** — list, accept/close/delete tickets, and chat with users.
- **AI chat monitoring** — monitor user↔AI conversations, accept a human representative, and manage AI settings (enable/disable, system prompt, escalation and blocked keywords).
- **Telegram alerts** — automatic alerts for new support tickets, AI representative requests, and blocked users.

## Installation

```bash
# 1. Clone the repository
git clone <your-repository-url> biteo-business
cd biteo-business

# 2. Fetch dependencies
flutter pub get

# 3. Configure Firebase (regenerates lib/firebase_options.dart
#    and android/app/google-services.json against your project)
#    Requires the FlutterFire CLI:  dart pub global activate flutterfire_cli
flutterfire configure -p <your-firebase-project-id>

#    Alternatively, place android/app/google-services.json manually
#    (see android/app/google-services.json.example for the expected shape).
```

## Environment Configuration

This project does **not** load a `.env` file at runtime. Configuration is supplied at **compile time**:

- **Firebase options** — compile-time constants in `lib/firebase_options.dart`, generated by `flutterfire configure`.
- **Admin TOTP secret** — compile-time constant read via `String.fromEnvironment('ADMIN_TOTP_SECRET', ...)` in `lib/auth_screen.dart`.

```bash
# Provide the TOTP secret at build/run time:
flutter run --dart-define=ADMIN_TOTP_SECRET=<your-base32-secret>
```

`.env.example` documents every configuration value and where it is sourced. It is **documentation only** and is **not automatically loaded by Flutter**.

## Deployment

- **Web:** `flutter build web --release` produces a static bundle in `build/web/` that can be hosted on Firebase Hosting, Cloud Run, or any static host.
- **Android:** `flutter build apk --release` (or AAB for Play Store). Configure production signing (`android/app/build.gradle.kts` currently uses debug signing — see `build.gradle.kts` TODO).
- **Firebase:** Firestore, Storage, Authentication, and the notification push endpoint must be configured in the Firebase console. Firestore/Storage security rules are **not** present in this repository and must be reviewed and applied in the console.
- **Push notifications:** the client POSTs to a Cloud Run endpoint (`lib/notification_sender_screen.dart`). See [docs/deployment.md](docs/deployment.md).

See [docs/deployment.md](docs/deployment.md) for the full deployment guide.

## Security

- **Never commit secrets.** `.gitignore` excludes environment files, `google-services.json`, keystores, and key properties.
- Real Firebase configuration, the admin TOTP secret, and Telegram credentials must be supplied at build time and **never** committed.
- **Client-side TOTP is not secure authentication.** It is a `CRITICAL SECURITY ARCHITECTURE ISSUE`. See [docs/security.md](docs/security.md) for details and the recommended path to server-side authentication.
- If the admin TOTP secret or any Telegram token has been exposed, rotate it before release.
