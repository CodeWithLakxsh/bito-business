# Environment & Configuration

## How Biteo Business gets its configuration

Biteo Business does **not** load a `.env` file at runtime. It uses **compile-time configuration**:

1. **Firebase options** — compile-time constants in `lib/firebase_options.dart`, generated by the FlutterFire CLI (`flutterfire configure`).
2. **Android Firebase file** — `android/app/google-services.json`, consumed by the Google Services Gradle plugin during Android builds.
3. **Admin TOTP secret** — `String.fromEnvironment('ADMIN_TOTP_SECRET')` in `lib/auth_screen.dart`, supplied with `--dart-define`.
4. **Telegram credentials** — constants in `lib/telegram_service.dart`.
5. **Push endpoint URL** — constant in `lib/notification_sender_screen.dart`.

`.env.example` at the repository root is **documentation only**. It is **not automatically loaded by Flutter**. No environment-file loader package is used, and one should not be introduced without a real need.

## Variable reference

| Variable | Purpose | Sourced from | Supply mechanism |
|---|---|---|---|
| `ADMIN_TOTP_SECRET` | Base32 shared secret for the client-side TOTP admin gate | `lib/auth_screen.dart` | `--dart-define=ADMIN_TOTP_SECRET=<value>` |
| Firebase options (`apiKey`, `appId`, `messagingSenderId`, `projectId`, `authDomain`, `storageBucket`, `measurementId`) | Firebase client bootstrap | `lib/firebase_options.dart` | `flutterfire configure` (regenerates the file) |
| Android Firebase client identifiers | Android Firebase bootstrap | `android/app/google-services.json` | `flutterfire configure` or manual placement from the Firebase console |
| `TELEGRAM_BOT_TOKEN` | Telegram bot token for alerts | `lib/telegram_service.dart` | edit source (currently placeholder) |
| `TELEGRAM_CHAT_ID` | Telegram chat to receive alerts | `lib/telegram_service.dart` | edit source (currently placeholder) |
| Push endpoint URL | Cloud Run push endpoint | `lib/notification_sender_screen.dart` | edit source |

## Local development example

```bash
flutter run --dart-define=ADMIN_TOTP_SECRET=<your-base32-secret>
```

## CI example

```bash
flutter build web --release --dart-define=ADMIN_TOTP_SECRET=CI_PLACEHOLDER
```

CI uses a harmless placeholder; production builds substitute the real value supplied through a secure channel (e.g. CI secret → `--dart-define`), never a hardcoded real value.

## Security rules

- Never commit real values for the variables above.
- `.env.example` is safe to commit because it contains only placeholders.
- Real credentials must be provided at build time through a controlled channel and kept out of version control.
